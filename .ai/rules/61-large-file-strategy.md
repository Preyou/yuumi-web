# P1-LARGE-FILE-STRATEGY

Priority: P1
Scope: `src/**`

## Rule
- 对超大文件新增功能时，优先采用“先拆后加”策略，避免继续堆积复杂度。
- 触发边界：当单文件超过 600 行且本次改动包含新增功能（非纯缺陷修复）时，必须先产出拆分计划（拆分目标、文件边界、实施顺序）。
- 拆分计划给出后，必须暂停并向用户确认，再继续实施代码改动。
- 对仅修复局部缺陷的改动，可不强制拆分，但不得显著扩大单文件复杂度。
- 新增复用逻辑必须放入语义正确目录，避免把跨页面能力留在页面文件中。

## Non-Goals
- 不要求一次性重写所有历史大文件。
- 不限制具体拆分粒度与命名细节。

## Exceptions
- 若拆分会显著增加发布风险，可暂缓，但需记录原因与后续拆分计划。

## Checks
- 检查超大文件新增功能是否先给出拆分计划。
- 检查触发边界是否按“>600 行 + 新增功能（非纯缺陷修复）”判定。
- 检查拆分计划后是否已暂停并获得用户确认。
- 检查新增逻辑是否落在正确模块边界。
- 检查是否出现“仅为赶工继续堆积”的实现方式。
