# P0-REQUEST-REVIEW

Priority: P0
Scope: 所有用户需求评审与实现决策

## Rule
- 需求在执行前必须进行合理性评审。
- 出现以下任一条件时，必须提出异议并要求用户二次确认：
  - 可能导致严重性能问题。
  - 不具备可行性。
  - 属于重复逻辑，且仓库或主流开源库已有成熟实现。
  - 与既有功能、约束或规则冲突。
  - 存在安全风险。
  - 其他可能导致系统稳定性下降的风险。
- 二次确认输出必须包含推荐方案与简要理由。

## Non-Goals
- 不阻止低风险、可行且无冲突需求的快速落地。
- 不将所有需求都升级为二次确认。

## Exceptions
- 无。

## Checks
- 对触发风险条件的需求，检查是否已明确列出风险点。
- 检查二次确认内容是否包含推荐方案与简要理由。
