# P1-TOAST-USAGE-BOUNDARY

Priority: P1
Scope: `src/**`

## Rule
- `$toast` 仅用于“需要全局提醒用户”的重要结果；默认不通知。
- 对于同一个请求结果，只允许一个提示渠道：
  - 若已由 `createApi(..., { notify })` 自动提示，则页面层不得再次 `$toast` 同一结果。
  - 若页面层要接管提示，必须通过 `notify: false` 或 `notify: { success: false } / { error: false }` 关闭对应自动提示。
- 表单校验错误（前端规则校验、后端可映射到字段的校验错误）应直接展示在表单项附近，不使用 `$toast`。
- 自动触发请求（初始化加载、watch 联动、轮询、后台刷新）默认不做成功 `$toast`。
- 无关紧要或可通过局部 UI 感知的结果（局部状态变化、轻量刷新完成）不提示。
- 仅当错误无法在局部 UI 清晰表达且需要用户立即感知时，才显示一次错误 `$toast`。

## Non-Goals
- 不禁止在关键流程中使用 `$toast`。
- 不规定具体组件库样式与文案风格。

## Exceptions
- 会话失效、权限撤销、关键写操作失败等全局中断事件，可直接使用 `$toast` 提示。

## Checks
- 检查同一请求是否出现“自动提示 + 页面 `$toast`”重复提示。
- 检查表单校验失败是否错误地使用了 `$toast`。
- 检查自动加载/后台刷新是否滥用成功 `$toast`。
- 检查提示触发点是否确实属于“全局需要感知”的事件。
