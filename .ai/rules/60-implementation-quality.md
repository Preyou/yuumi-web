# P1-IMPLEMENTATION-QUALITY

Priority: P1
Scope: `src/**`

## Rule
- 避免单文件过大，保持模块边界清晰。
- 数据渲染与业务逻辑尽量分离。
- 可复用逻辑应抽象为可复用单元，避免在视图层堆积实现细节。
- 表单必须具备校验与错误提示。
- 默认禁止在业务层吞掉异常（如空 `catch`、捕获后返回伪默认值、记录日志后继续成功流程）。
- 对不可恢复的底层错误必须抛出并中断；允许提示用户，但提示不能替代失败状态。

## Non-Goals
- 不强制统一的函数长度或文件行数阈值。
- 不限制具体的状态管理方案。

## Exceptions
- 临时调试代码可短期存在，但提交前应清理。

## Checks
- 检查页面组件是否承载过多与渲染无关逻辑。
- 检查表单交互是否覆盖失败路径与用户可见错误提示。
- 检查失败路径是否真实失败（`throw` / 明确失败态），而不是被兜底改写为“看起来成功”。
